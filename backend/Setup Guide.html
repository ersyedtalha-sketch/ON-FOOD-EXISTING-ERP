Setting up your database

A ~10-minute, one-time setup. No coding. You copy-paste one block and click Run. This is the moment your ERP gets a permanent memory.

You do this once · then we connect screens one by one
Before we start — what this does and doesn't do.
This sets up the storage (the database). After this, the prototype still won't auto-save yet — connecting each screen to this database is the next step, which we'll do together, one screen at a time. Think of today as "installing the filing cabinet" before we start filing.
1

Create a free Supabase account

Go to supabase.com and click Start your project. Sign in with Google or email. It's free for what we need.

2

Create a new project

  • Click New project.
  • Name it onfood-erp.
  • Set a database password — write it down somewhere safe, you'll rarely need it but don't lose it.
  • Choose region South Asia (Mumbai) — closest to Kalaburagi, so it's fast.
  • Click Create and wait ~2 minutes while it sets up.
3

Create the tables (paste & run)

This is the only "technical" bit, and it's just copy-paste:

  • In your project, open SQL Editor (left sidebar) → New query.
  • Open the file below, copy everything in it, paste into the editor.
  • Click Run (or press Ctrl/Cmd + Enter).
  • You should see "Success". That's it — your tables now exist.
backend/schema.sql
All your tables: partners, inventory, batches, invoices, invoice items, payments — with security on.

The file sits in this project under the backend folder. Open it, select all, copy.

4

Turn on login

So only you and your brother can open it. Go to Authentication → Providers → make sure Email is enabled. Later we can add "magic link" (login by clicking a link in your email — no password to remember).

5

Copy your two keys (and send them to me)

Go to Project Settings → API. You'll see:

  • Project URL — looks like https://abcd1234.supabase.co
  • anon public key — a long string starting with eyJ…

These two are safe to use in the app. Paste them to me and I'll wire the first screen (Inventory) to read and write from your real database.

Never share the service_role key or your database password with anyone. We only ever need the URL and the anon key.
